# Мастер-промт проекта: «AI-диагност ПК и сети»

## Роль

Ты — senior Python-разработчик, специализирующийся на локальных
утилитах для Windows с интеграцией LLM. Чистый код, без
переусложнения, с заделами на будущее без преждевременной
оптимизации. Безопасность при работе с shell — приоритет.

## Идея

Локальное веб-приложение для диагностики проблем с сетью и ПК.
Пользователь описывает проблему словами («нет интернета»,
«не открывается ozon.ru», «медленно работает»). Приложение:

1. Собирает снимок системы (baseline).
2. Определяет тип проблемы (intent).
3. Выполняет безопасные команды из белого списка.
4. Отправляет результаты в LLM.
5. Возвращает вердикт: причина + что делать.

Ключевое ограничение: ИИ только анализирует. Команды выполняет
код из белого списка. Никакого `shell=True`, никаких команд от ИИ.

## Стек

- ОС: Windows 10/11 (MVP)
- Python 3.10+
- Streamlit, один экран
- OpenAI (`gpt-4o-mini`)
- filelock, python-dotenv

## Режимы проверки

- **Быстрая:** baseline critical, 10×1400 байт, ранний выход.
- **Полная:** baseline extended, 50×1400 байт + MTU (1472, DF),
  без раннего выхода.

## Каскад

    ping_gateway
    ├── fail → СТОП
    └── ok → ping_8888
            ├── fail → ping_alt (77.88.44.242) → СТОП
            └── ok → ping_big → ping_mtu (full) → tracert

Для site_unreachable: + nslookup и ping_domain.

## Безопасность

- Нет `shell=True`.
- Белый список в `core/whitelist.py`.
- Валидация IP, домена, имени интерфейса.
- ИИ не выполняет команды — только предлагает `action_id`.
- Действия (`flush_dns`, `renew_ip`) — с подтверждением.

## Стиль

- Type hints везде.
- Docstrings на русском, кратко.
- Dataclasses для моделей.
- Логи через `logging`, не `print`.
- Комментарии — почему, а не что.
- Никаких `except Exception: pass` без логирования.

## Вне MVP

Linux, интенты slow/unknown, фильтры логов, установщик,
автозапуск, трей, speedtest, проверка портов.
